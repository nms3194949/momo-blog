# 理財百科寫作規則

排程任務（每週 2 篇）和人工撰寫都照這份規則。網站其他部分的規則以 repo 為準。

## 位置與格式

- 一篇一個資料夾：`src/content/guide/<網址代稱>/index.md`，網址代稱用 `guide-queue.yml` 裡的 `slug`（英文小寫加連字號），上線後不要改。
- 理財百科**不放圖片**、不出現在首頁和 IG 文章的主題頁；有自己的目錄 `/guide/`。
- 發布時間：寫好當下的 **2 天後 20:30（台灣時間）**，例如 `date: 2026-11-12T20:30:00+08:00`。時間到由 GitHub Actions 自動上架；MOMO 在這 2 天內可以要求修改或撤下（撤下＝刪掉資料夾或加 `draft: true`）。

```yaml
---
title: "讀者會問 AI 或搜尋的問句，例如：配息率是什麼？配息率高就代表報酬高嗎？"
description: "160 字以內，一句話說明這篇回答什麼"
summary: "一句話答案：2–3 句直接回答標題，能被單獨引用的完整句子"
date: 2026-11-12T20:30:00+08:00
category: 名詞解釋        # 名詞解釋／常見疑問／比較選擇／試算觀念（四選一）
keywords: [配息率, 年化配息率, 配息基金]
tags: [配息基金]          # 只能從 6 個主題挑 1–2 個：資產配置、配息基金、現金規劃、美債與利率、市場判讀、投資觀念
faq:
  - q: 問題？
    a: 能獨立成立的完整回答。
sources:
  - name: 來源名稱（日期）
    url: https://...
---
```

## 內文結構（約 1,500–2,500 字）

1. 開頭一段：用 2–3 句再講一次答案，加上這件事為什麼重要。
2. 3–5 個 `##` 小標題，寫成讀者會問的問句。
3. 至少一個**表格**或**具體例子**（試算、對照）。試算要實際驗算，數字下方加：`> 數字為假設情境試算，非績效預測，也不代表建議配置。`
4. 「常見誤解」或「要注意的地方」一段。
5. 最後一段固定為 `## MOMO 的配置觀點`：把名詞連回資產配置與長期現金流，不給買賣或時點建議。
6. FAQ 3–4 題，答案要能單獨被引用。
7. **內部連結**：連 1–2 篇相關的理財百科（`../<slug>/`）或 IG 文章（`../../posts/<資料夾>/`），只連已經存在的文章。

## 內容規則（必守）

- **只寫觀念、定義、計算方法**，屬於長期有效的內容。不寫「現在該買／該賣」、不給時點建議、不預測行情。
- **事實要查證**：定義、公式、制度、法規用 WebSearch／WebFetch 查證，優先引用主管機關、交易所、公會、央行、學術或大型財經媒體；`sources` 至少 2 個、附網址。查不到的說法不要寫。
- 如果需要市場數字（例如歷史平均），一定標註資料期間與來源；**不寫會很快過期的即時數字**。
- 不提特定基金、特定保險公司、特定投信或銀行名稱；不用「保單基金」「投資型保單」，只說「基金」。
- 避免「保證」「穩賺」「穩定配息」「推薦買進」「抄底」「必漲」。「穩定的現金流」改成「長期的現金流」。
- 配息相關內容一定要提醒：**配息不等於投資報酬，要看配息＋淨值變化的總報酬；配息可能來自本金。**
- 報酬率假設**最高 6%**，而且一定要寫出「假設年化報酬率 X%」。
- 不寫「市場無法預測，但資產可以配置。」（首頁標語，內文不重複）。
- 作者是明哲MOMO、品牌是 MOMO雙贏策略；不寫「財務顧問」「理財顧問」等職稱。
- 粗體 `**` 不可緊貼在「中文字＋全形符號」之間：`而是**「沒想過」**` 錯誤，要寫成 `而是「**沒想過**」`。
- 語氣：專業但白話，像在跟第一次接觸的朋友解釋；繁體中文、台灣用語。

## 驗證（push 前必跑）

```
python3 scripts/check-guide.py src/content/guide/<slug>
npx astro build   # 未來日期的文章不會出現在 dist，可暫時把 date 改成過去確認後改回
```

## 題目清單

`content-plan/guide-queue.yml`：依順序挑第一個 `status: todo` 的題目，寫完改成 `status: scheduled` 並填上 `date`。MOMO 可以隨時調整順序、新增或刪除題目。
